BITACORA DE DESARROLLO

Salam DataBase, subsistema aislado creado para implementarlo al proyecto SALAM, crea una base de datos para almacenar la informacion de inventario
y ventas en tablas con una estructura definida en Data/database.sql

Distribucion de responsabilidades:

Data : se encarga de guardar la base de datos y scripts relacionados incluyendo la estructura de las tablas y relaciones entre ellas.
Forms : se encarga de la interfaz de usuario, permitiendo a los usuarios interactuar con la base de datos a través de formularios y vistas.
Models : se encarga de la representación de los datos mediante entidades DTO
Repositories : se encarga del acceso a datos, implementando las operaciones CRUD (Crear, Leer, Actualizar, Eliminar) sobre las entidades DTO.
Services : se encarga de la lógica de negocio, coordinando las operaciones entre los repositorios y los formularios, y aplicando reglas de negocio según sea necesario.
Utils : se encarga de modulos auxiliares

ilustracion de esquema de base de datos

el sistema cuenta con varias entidades para describir movimientos, en primer lugar las categorias son muy generales respecto a los productos,
luego las subcategorias diferencian entre modelos(categoria) y tipos especificos de esos modelos(subcategoria), luego los productos son los modelos
especificos de cada subcategoria, y finalmente las presentaciones son las variantes de cada producto, por ejemplo un producto puede tener varias presentaciones como diferentes tamaños o colores.

para registrar compras a proveedores se usa la tabla compra y el detalle de la compra se hace en la tabla detalle_compra, donde se especifica la presentacion del producto comprado, la cantidad y el precio de compra.
igualmente para venta con la misma dinamica.

movimiento inventario sirve para cuando se requiera hacer una operacion de movimiento de inventario por ejemplo cuando se hace un ajuste de inventario o una transferencia entre almacenes,
se registra en esta tabla especificando la presentacion del producto, la cantidad y el tipo de movimiento (entrada, salida o desempaquetado).

Objetivos:

1. permitir el registro de productos, proveedores y clientes en la base de datos.           LISTO
2. permitir el registro de compras y ventas, incluyendo el detalle de cada transacción.     LISTO
3. permitir el registro de movimientos de inventario, incluyendo ajustes y transferencias.  EN PROCESO
